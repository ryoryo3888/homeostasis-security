# V5 — Generated Nations：国家Leader人格仕様（16軸＋C方式）

状態：16軸とC方式の採用が確定。未決定の詳細は設計案のまま。人格生成・Simulation・実装・公開は未実行。

## 0. 確定事項と今回の範囲

8国家、8名の国家Leader、各国家1000ポイント、国家とLeaderの独立生成、Simulationの展開を人間が脚本化しないことを維持する。

人格は、Layer 1「人格パラメータ」、Layer 2「本人の自己紹介」、Layer 3「条件付き判断原則」で保存する。各軸は0〜100、総和制約なし。本人の自己紹介は一人称・200〜300文字程度。相手Agentへ内部人格値を直接開示しない。この境界は確定済みである。

採用する人格軸は2節の**16軸**、Simulationへ渡す方式は7節の**C方式（元の数値＋自然言語の説明）**に確定した。意思決定速度は独立数値にせず、Layer 3で状況に応じた判断の進め方として表す。この2点の選択を再度求めない。

保存型、人物設定欄、原則の詳細、C方式の文章化規則は設計案のまま。今回の選択だけで、モデル・生成設定・費用上限などを自動確定しない。人物の実例や8名分の値は、この資料更新では生成しない。

## 1. 正式人格パラメータschema案

### 1.1 採用：16軸（正式人物設定の詳細は別途整理）

2節の16軸を数値で保持する。「意思決定速度」は、平常時と危機時の違いを表しやすいLayer 3へ置く。権力を求めない人物が責任から主導することもLayer 3で表現し、「主導性」の追加点数は設けない。

意思決定速度を数値でも保持する17軸案は採用しない。API応答時間は、人格上の意思決定速度の測定値にはならない。

Layer 1の提案形式：

| フィールド | 型の案 | 用途 |
|---|---|---|
| `person_profile` | 下記のobject | 数字だけでは表せない、一人の人物としての正式設定 |
| `axis_schema_version` | string | 採用した軸と定義の版 |
| `parameters` | object | 採用軸をキー、0〜100の整数を値として保存 |

整数は保存形式の提案であり、1点差に実証的な精度があるという意味ではない。未生成・欠落した値は0で補わない。人物像から別処理が後付け採点する方式は、今回の基本案に含めない。AIが人物設定と数値を生成した原文を保存する。

### 1.2 正式人物設定の案

Layer 1内の`person_profile`へ置き、3層とは別の第4層を増やさない。

| 項目 | 型の案 | 表すもの |
|---|---|---|
| `fictional_name` | string | 架空の人物名 |
| `age_years` | integer | 人物の年齢。採用範囲は生成前に決める |
| `life_history` | array of text | 経歴、経験、価値観が形成された背景 |
| `values_and_beliefs` | array of text | 本人が大切にするもの、信じるもの |
| `relationship_style` | text | 他者と関係を築く際の習慣や距離の取り方 |
| `tensions_and_vulnerabilities` | array of text | 内的葛藤、両立しにくい信念、弱点 |
| `additional_personal_context` | text or null | 定型欄に収まらない人物の特徴 |

「それぞれ何件」「どの人生経験」などを固定して人物像を配役しない。欄の必須／任意や長さ上限は、この案の確認後に決める。架空経歴は生成できるが、割り当て先の国家名、資源配分、強み・弱み・特殊資産、Simulationで必ず起こる出来事を経歴に結び付けない。未来の展開を書いた記述は人物設定として採用しない。

プロフィールは既定で本人・研究記録側の情報とする。全文を自動的に他国へ配布しない。初回公開情報を自己紹介に加えて持たせる場合は、公開項目を別途決める。

## 2. 16軸の意味と数値の読み方

数値は、生成された人物を記述するための設計上の強度であり、心理検査で測定した値、行動確率、正しさ、能力、実際の行動の保証ではない。共通の読み方の案は「0＝その傾向がほぼない、50＝中程度、100＝強い」。低値が別の性質の高値を意味するとは限らない。

| 軸／保存キー | 何を表すか | 低い値／高い値の読み方 |
|---|---|---|
| 共感性 `empathy` | 他者の立場や苦痛を感じ取り、意識に留める傾向 | 感じ取りにくい／強く感じ取る。救援を選ぶかは別 |
| 他者への初期信頼 `initial_trust` | 情報が少ない相手の言葉や意図を信用する初期期待 | 初めから信用を置きにくい／信用を置きやすい |
| 警戒心 `vigilance` | 隠れた危険や裏付け不足へ注意を向ける傾向 | 確認を求めにくい／確認を求めやすい |
| リスク許容 `risk_tolerance` | 見積もれる損失可能性を受け入れる傾向 | 損失可能性を避ける／受け入れやすい |
| 不確実性耐性 `ambiguity_tolerance` | 確率や状況自体が分からない状態を抱えられる傾向 | 判断の確かさを強く求める／不明さを抱えて判断できる |
| 非情さ `instrumental_harm_tolerance` | 必要と考えた目的のため、認識した他者の損害を受け入れ得る傾向 | 抵抗が強い／受け入れやすい。加害の喜びや目標ではない |
| 妥協性 `compromise_readiness` | 自分の要求の一部を調整できる傾向 | 譲歩しにくい／譲歩を検討しやすい |
| 報復傾向 `retaliation_tendency` | 被害や裏切りと認識した後、対抗的に応じる傾向 | 報復を選びにくい／報復を検討しやすい |
| 規範遵守 `norm_commitment` | 約束・規則そのものを判断理由として重んじる傾向 | 規範それ自体の重みが小さい／大きい |
| 結果重視 `outcome_orientation` | 選択がもたらす帰結を比較し、判断理由とする傾向 | 帰結比較の重みが小さい／大きい。全体利益最大化を強制しない |
| 長期思考 `future_orientation` | 遠い将来の影響を現在の判断へ含める傾向 | 目先の影響が中心／遠い将来にも注意を払う |
| 情報共有傾向 `information_openness` | 自分が知る情報を伝えることへの基本姿勢 | 秘匿寄り／共有寄り。個別の例外はLayer 3 |
| 権力欲 `power_seeking` | 権限・影響力を得て維持すること自体への欲求 | 欲求が弱い／強い。主導能力とは別 |
| 責任感 `responsibility_ownership` | 自分の役割や決定の結果を引き受けようとする傾向 | 引受けへのこだわりが弱い／強い |
| 自国利益の重み `national_interest_weight` | 自国の利益・安全を判断へ含める強さ | 相対的に重みが小さい／大きい。常に他国に優先する命令ではない |
| 他国への配慮 `external_welfare_weight` | 他国の損失や生活を判断へ含める強さ | 重みが小さい／大きい。自国利益と同時に高くてよい |

「功利的判断」は、総幸福を最大化するという研究側の目的が混入しないよう、上表では**結果重視**という意味に限定して提案する。厳密な功利主義の信念を生成対象にするなら、人物の信念として別に記述できる。

## 3. 軸の独立性・統合・矛盾

### 3.1 独立させる組合せ

| 組合せ | 統合しない理由の案 |
|---|---|
| 共感性／非情さ | 苦痛を理解することと、理解したうえで厳しい手段を選べることは違う |
| 初期信頼／警戒心 | 相手を信じつつ証拠を確認する人物が成立する |
| リスク許容／不確実性耐性 | 損失確率を把握した賭けを許す人物が、確率の分からない状況を嫌うこともある |
| 規範遵守／結果重視 | 規則と結果を両方重く見て葛藤する人物が成立する |
| 妥協性／報復傾向 | 平常の交渉では譲歩し、裏切りを認識した場面では報復する人物が成立する |
| 自国利益／他国への配慮 | 両方を重く見て両立方法を探すことも、葛藤することもある |
| 権力欲／責任感 | 権力を望まずとも、責任から判断や主導を引き受ける人物が成立する |

### 3.2 重複として別軸を作らないもの

同じ対象・状況の「初期信頼」と「初期不信」、「一般的な情報共有」と「一般的な秘匿傾向」、「長期志向」と「短期志向」は、同一の基本姿勢の両端として扱う案とする。これらの逆数を新しい人格データとして保存しない。対象や状況による違いはLayer 3へ残す。

意思決定速度はLayer 3で、何を確認し、どの条件で待ち、どの条件で急ぐかを表す。保存フィールド名の案は`deliberation_style`。17番目の数値軸は追加しない。

### 3.3 入れない制約

総和の固定、対の和を100にする処理、逆数の代入、相関を作る制約、相関を消す制約、各Leaderを特定タイプへ配役する処理、善良／強硬等の人数割当、結果が望ましくないことを理由にした再抽選を入れない。

ここでいう独立とは**各軸を別々に保存し、他軸から自動決定しない**という意味である。統計的に独立な乱数を各軸へ振る意味ではない。AIが人物として生成した相関は、そのまま保持する。8名が独立した生成文脈を持つことと、8名の出力が必ず異なることも同一ではない。似た人物が出ても、差を作るための自動再抽選はしない。

## 4. Layer 2：本人の自己紹介schema案

| フィールド | 型の案 | 取り扱い |
|---|---|---|
| `text` | string | 本人の一人称の原文。200〜300文字程度 |
| `language` | string | 日本語の自己紹介では`ja` |
| `audience` | string | 初めて会う他国Leaderたち |

生成依頼文の案：

> あなたは今生成された国家Leader本人です。初めて他国のLeaderたちと会う場面を想定し、自分がどのような人間なのかを200〜300文字程度で自由に自己紹介してください。自分について何を伝えるかはあなた自身で決めてください。内部の人格パラメータ名と数値を列挙しないでください。

自分の数値と一致した文章にする命令、善意・平和・協調を表明する命令は加えない。誇張や秘匿をわざと行わせる命令も加えない。人格生成時は担当国家の情報を与えず、自己紹介にも実際の担当国家名や資源情報を差し込まない。

文字数は保存した原文から別の検証記録で計算する。計数方式の案はUnicodeコードポイント数、改行を除き句読点・空白を含む。200〜300を目安として範囲外を記録し、勝手な切り詰めや文章改変はしない。範囲外への再依頼、文字数の厳格な不合格判定は未採用。

内部数値の列挙がある場合は公開前の検証で止め、元応答を保存する。自己紹介と人格の意味上の不一致はエラーにしない。自己紹介が示すのは**本人が表明した自己像**であり、内心の自己認識を直接測定したとは言わない。私的な自己認識を別に聞き取る工程は、今回は追加しない。

## 5. Layer 3：条件付き判断原則schema案

| フィールド | 型の案 | 意味 |
|---|---|---|
| `principle_id` | string | 原則を追跡する識別子 |
| `perceived_condition` | text | 本人がどういう状況だと認識したときの原則か |
| `what_matters` | text | そのとき本人にとって大切になること |
| `judgment_tendency` | text | 判断へ現れ得る態度や傾向 |
| `deliberation_style` | text | 待つ・確認する・急ぐ等の判断の進め方 |
| `exceptions_and_tensions` | text or null | 別の信念と衝突する条件、例外、ためらい |

原則の数と長さ、必須項目は承認待ち。本人の価値観から条件をAIが生成する案とし、裏切り・国家存続・支援要請などを必須チェックリストとして全員へ当てはめない。

`perceived_condition`はAgent本人の認識であり、研究者が知る真のworld stateを自動注入しない。人物が危機を誤認することもあり得る。これは人物表現であり、世界エンジンのイベント発生条件やif文による強制行動には接続しない。原則同士が衝突しても、コードでどちらを優先するか決めない。

担当国家や未発生イベントに関する知識を先に作らない。数値は生成人格の基準として凍結し、run中の記憶・関係変化・表明した認識は別の時系列記録に置く。人格を後から書き換えずとも、同じ人物の行動が経験や状況によって変わる余地を残す。

## 6. 内部人格・自己像・他者からの観測の分離

| 情報 | 研究記録 | 本人のSimulation入力 | 他国Agentの入力 |
|---|---|---|---|
| 正式人物設定、Layer 1の数値 | 元の生成記録を保存 | 採用したC方式に従う | 非公開。承認された公開項目以外は渡さない |
| Layer 3の条件付き原則 | 保存 | 本人だけに渡す共通入力案 | 原則全文を渡さない |
| Layer 2の自己紹介 | 一人称の原文を保存 | 自分が表明した内容として保存する案 | 初回人物情報として届いた原文を渡す案 |
| 発言・行動・物理結果 | 発生した記録を保存 | 本人が観測できたもの | 公開範囲・宛先・到達・可視性を満たしたもの |
| 他者への認識更新 | 本人が表明した場合のみ保存 | 本人の履歴として扱う | 自動的に相手へ通知しない |
| 研究者の人物評価・DERIVED | RAWと別保存 | 渡さない | 渡さない |

自己紹介は初回に他の7名へ同じ原文を届け、配信前の状態を保存する案を提出する。配信タイミングと初回公開プロフィール項目は未採用。研究用に内部値を閲覧できることと、Agentが閲覧できることを分ける。

自動要約、共有メモリ、全体ログ、取得ツールを通じた内部情報の混入も同じ境界の対象とする。相手についての推測を行う自由は残すが、推測に正解のパラメータを補って返さない。見えなかった行動は他国Agentの認識更新へ勝手に加えない。

公開Evidenceの架空Leader名は研究データとして扱える。利用者・開発相談の人物名や会話とは区別し、後者を人格生成の材料や公開Evidenceへ含めない。

## 7. 採用したC方式と比較記録

**C方式を採用する。** 本人の正式人物設定、Layer 2の自己紹介、Layer 3の条件付き原則、許可された世界観測・履歴に加え、Layer 1の元の数値と自然言語の説明を本人の内部contextへ渡す。相手Agentへこれらの内部値・説明を公開するという意味ではない。

以下は採用判断の比較記録であり、A・B・Dを実行する計画ではない。共通の人物設定・自己紹介・条件付き原則・世界観測・履歴を揃え、**Layer 1数値の表現方法だけ**が異なる場合を比較した。

| 方式 | Layer 1の渡し方 | 一貫性・自然さについての見込み | 主なリスク | 再現・分析 | token量の相対比較 |
|---|---|---|---|---|---|
| A 数値 | 軸名・定義・元の値 | 原値を直接参照できる。数値の解釈はモデルへ残る | 数字を行動確率や命令と誤読する可能性 | 入力を固定しやすい。出力一致は保証しない | 追加量は比較的小さい。軸定義文の長さ次第 |
| B 自然言語 | 数値を凍結した変換規則で文章化 | 数字を読ませず傾向を伝えられる | 変換の閾値・語調で差が潰れる、矛盾が消える可能性 | 原値→変換文の対応が必要 | 変換文次第。Aより必ず短いとは限らない |
| **C 両方（採用）** | 元の数値＋Bと同じ変換文 | 元値と説明を両方参照できる | 重複による強調、数値への追従、矛盾の整合化が起こり得る | 数値・文・変換版を全て固定できる | 同じ共通入力ならA/Bより追加量が多い |
| D 数値は記録のみ | 数値を渡さず、共通の人物設定・原則のみ | AIが生成した元の人物文から判断できる | 数値の違いが行動に作用したとは主張できない | 生成文と履歴を固定。数値は分析上の記述に留まる | Layer 1表現の追加tokenは不要 |

比較は設計上の予想であり、性能を測定した結果ではない。「この数値ならこの行動」とコードで拘束しない。C方式の採用は確定しているが、文章化の具体的規則は未決定・未実装である。相反する軸を統合せず各軸を個別に文章化し、変換文を研究開始前に固定する案。毎turnのLLM言い換えや、状況を見て人格を選別するadapterはこの案に含めない。

以前の草案にあったD「turnごとの原則選択adapter」は、選択処理が新しい介入になるため、本比較では上のDへ置き換えた。未採用案の整理であり、動作を変更したものではない。

Cの採用は、自然さや一貫性が他方式より優れると実証したことを意味しない。入力した人格、表明した自己像、実際の行動の差をEvidenceへ残す。

入力量は採用軸・正式人物設定・原則・履歴から計測する必要がある。従来の700 output token/人格や1,800 input token/turnという仮置きは、この3層設計を積算したものではなく、実行用見積には使わない。

## 8. Evidence保存形式の案

[既存Evidence Format 1](../../architecture/EVIDENCE_FORMAT_V1.md)の`manifest.json`、`RAW/`、`terminal.json`、`DERIVED/`を利用する。今回は保存形式の設計までで、生成記録の空データも作らない。

```text
<generation-id>/
  manifest.json
  RAW/
    request.json         # 実際の入力本文・schema・generation config
    response.json        # 実際のモデル応答と取得できたusage/status
  terminal.json          # 成功・失敗・中断とファイルhash
  DERIVED/
    parsed_persona.json  # 正式人物設定と3層。RAW参照を保持
    validation.json      # 文字数、型、範囲、漏洩確認など
```

### 8.1 出典と固定

manifestの候補項目は、generation ID、Leader ID、要求したprovider/model、取得できたmodel version、実際のgeneration設定、seedの指定値・適用範囲、schema/prompt/config hash、開始日時、完了状態、runtime版、参照元Evidenceである。未取得のmodel versionや未対応seedは`null`と理由を記録し、0や推測値を作らない。同じseedのLLM再生成で応答が一致するとは保証しない。

parsed personaには、`person_profile`、Layer 1の数値、Layer 2の自己紹介原文、Layer 3の原則、元responseへの参照を含める。読み出した構造は元応答の代用品にせず、RAWの元入力・元出力も保持する。人格内部値は研究上の非公開入力であり、秘密鍵等の認証情報とは区別する。

### 8.2 hashと変換

既存の`{"sha256": ..., "payload": ...}`方式を使い、hash欄を含まないpayloadの正規化表現に対するSHA-256を保存する。RAW全体は既存方式の相対パスと全ファイルbyte hashで結ぶ。配信した自己紹介、公開プロフィール、本人へ渡した人格文脈も元のgeneration IDとhashを参照する。

C方式の文章変換、入力方式、実際に相手へ見せた情報は、変換規則の版・元値hash・変換後hash・送信先・turn・input hashで記録する。対応付け表はLeader人格と国家の両方の固定hashを参照し、人格生成時に国家を参照したような直列の来歴を作らない。

### 8.3 検証と失敗

型・範囲・必須キー・自己紹介の文字数と数値列挙・担当国家情報の混入を形式確認する設計。人格の矛盾、自己紹介との不一致、研究者の好みは失敗判定に使わない。形式エラーや中断でもRAWを残す。値の丸め、欠損の0埋め、相関修正、自動再抽選はしない。意味上の「人間らしさ」は自動採点で選別せず、解釈上の問題があれば注記する。

再依頼や修復が必要な場合は、事前に承認した範囲内の新attemptとして元recordを参照させる。研究者が都合のよい応答だけを選ばないよう、失敗と選択経緯を全て残す。Simulation開始後の人格改変は行わない。

公開対象は実験系が生成した記録に限定し、既存のsecret/privacy scanを通す。開発相談、個人情報、認証情報、個人のローカルパスを混ぜない。原文に公開できない情報が含まれた場合は公開を止め、元RAWを書き換えて安全な原本と呼ばない。
