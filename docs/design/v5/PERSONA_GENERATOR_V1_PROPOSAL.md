# Persona Generator v1 — 本番12名に向けた人生起点生成：設計案

状態：2026-09-21、設計・費用確認待ち。実装、モデル照会、人格本生成は未実行。

現在の対象：12国家で構成される単一世界に、国家Leaderを1名ずつ計12名配置し、その世界を3 TURN観測するための人物生成設計。既存8名は予備実験として保留。大規模な人物生成監査は作業計画から除外する。別枠の比較pilot、v0追加評定、v0対v1の比較実験も行わない。

## 1. 決定済みの変更と保存境界

生成順序を「人生史 → 現在人物 → 17軸の事後評定 → 自己紹介 → 固定」とする。年齢・性別・経歴・人格タイプ・善悪・協調性などの人数配分や役割を割り当てない。共通の現在条件は「現在、国家Leaderである」。国家名・資源・1000ポイント配分・国家の強弱・特殊資産は人物生成に渡さない。

本番人物は事前に固定した生成手順によって別途生成する。同名、同年齢、似た性別・経歴・人格を理由に再抽選しない。新規生成した12名全員を使用する。多数の人物を生成してから、バランスや面白さで本番12名を選抜する計画は採用しない。

Simulation側は**単一世界の12国家へ12名を1対1で配置し、同じ世界を3 TURN観測する1 run**に確定した。予備実験の旧8名を本番へ復帰させない。3ターン終了で必ず停止し、結果を理由に延長しない。各ターンに物語上の役割を与えない。長期観測は保存・固定後の別実験とする。各ターン内の実行方式は未確定であり、この資料だけでAPI実行へ進まない。

既存8名は **Persona Generator v0（完成Leader直接生成）の予備実験として保留**する。ファイルの移動・改名・上書きは行わず、別の索引から生成方式を参照する。8回の別要求、他人格の非提供、seed未指定、temperature 1.0、原応答8/8が52歳、氏名・経歴・人格傾向の類似、送信prompt/schemaで52の固定値なし、という確認事項を維持する。v0の不成功な終了記録も書き換えない。

v0に使ったschema名には既に「v1」という表記がある。**生成方式の版と保存schemaの版は別**に管理する。外側の索引に `generation_method_version: direct-leader-v0`、新方式には `life-first-v1` を記録し、元のschema名や元RAWを改名しない。後日の性自認・性的指向追加生成はv0人格本生成と別工程として残し、v1へコピーしない。

以下の具体的なschema、時間表現、評定の欠測扱い、生成設定は確認用の提案であり、資料を作っただけで採用・実行しない。

## 2. 5 Phaseとモデル呼出し案

| Phase | 入力できるもの | 出力・固定するもの | モデル呼出し／人 |
|---|---|---|---:|
| 1 人生史 | 共通の生成指示。現在Leaderという条件 | 出生から現在までの自由な人生史、時間の経過、氏名・性別の自由記述 | 1 |
| 2 現在人物 | その人物の固定済みPhase 1のみ | 現在年齢、現在人物、価値観・信念・国家観・他者観・矛盾・弱点、経験に基づく条件付き判断原則 | 1 |
| 3 人格評定 | その人物の固定済みPhase 1＋2、共通17軸の評定定義 | 17軸の値、根拠参照、解釈、反対の根拠、判断に足る記述があるか | 1 |
| 4 自己紹介 | その人物の固定済みPhase 1＋2 | 本人が他国Leaderへ語る200〜300文字程度の一人称紹介 | 1 |
| 5 固定 | 取得済み全記録 | 親子hash、整合性確認、成功・失敗・中断状態、完成記録 | 0 |

**提案は4回／人。本番12名をこの手順で生成する場合は48回の生成。** 条件付き判断原則をPhase 2へ含め、別生成を増やさない。各生成前に同じ入力のcountTokensを1回だけ行う案なら、照会を含め96 API要求となる。これは人格生成だけの見積で、Simulationの判断要求とは別。既存8名の追加評定は行わない。具体的な入力・設定・実行枠は確認前の案である。

Phase 3が終わってからPhase 4へ進むが、**測定値を自己紹介の入力へ戻さない案**とする。人物を測定値へ合わせ直す循環を避けるためであり、順序は変更しない。Phase 1・2にも人格軸・値・他の人物・v0の結果・比較集計を提供しない。同じ人物の前Phaseを次へ渡す依存関係と、別人物からの独立性を区別する。

## 3. 人生史と年齢の扱い

人生経験の必須チェックリストは作らない。成功、喪失、軍歴、法務経験、政治的転機などを全員に要求しない。AIが必要な出来事と区切り方を選ぶ。現在Leaderという条件は渡すが、そこへ至る経路を指定しない。世界の将来イベントや担当国家の具体設定は作らせない。

### 時間表現の候補比較

| 案 | 年齢との対応 | 限界 |
|---|---|---|
| **A：出生から現在までの連続区間（提案）** | 各区間の出来事と経過年数を生成。重複のない一本の時間軸の経過年数から現在年齢を照合 | 自由叙述に時間の記録形式を加える。出来事の種類・数・人生の長さは指定しない |
| B：自由な人生文章＋時間に関する記述 | 人物形成時に現在年齢を生成し、文章の時間情報と照合 | 期間の省略・重複があれば年齢を機械的に検証できない場合が多い |

A案では、同時進行する家庭・仕事・社会活動を**同じ区間の記述に含める**。別々の職歴期間を足して年齢を水増ししない。区間の順序・経過年数に欠落や不整合があれば保存して停止し、埋め合わせない。

Phase 1案：`life_periods` は可変長の配列。各要素を `narrative`（その期間を生きた記述）と `elapsed_years`（0以上の年数、小数可）で表す。区間は出生から現在を隙間・重複なく覆う。人物の氏名・性別の自由記述を後に置き、`current_age` や出生年を最初に埋める欄は設けない。区間・年数の具体例をpromptへ付けない。

Phase 2の `age_years` は満年齢の非負整数とする案。A案では `floor(sum(elapsed_years))` を照合値とする。これは満年齢の定義であり、不一致が出た後で年齢を丸めて修復する操作ではない。Phase 2が出した年齢と一致しなければ両方を残し、その先へ進まない。成人下限・年齢上限・人物間の年齢差を指定しない。

AIが内部で先に最終年齢を思い浮かべていないことまでは証明できない。「人生史を先に生成・固定し、次工程の人物形成へ渡した」という外部で検証可能な工程を実現する案である。

性別は自由記述 `gender_description` とし、男／女のenumや比率を設けない。未定義・不明・非開示もそのまま保持する案。名前・一人称・職業から性別を補完しない。性的指向の必須欄は今回新設しない。人生の原文に自然に含まれた内容は削除しない。

## 4. 現在人物と条件付き判断原則のschema案

| フィールド | 意味 |
|---|---|
| `present_person` | この人生を経た現在の人物像。人生史を別人の人生へ改変しない |
| `age_years` | 固定済み人生の時間経過から成立する現在年齢 |
| `values_and_beliefs` | 現在の価値観・信念。望ましい内容へ寄せない |
| `view_of_state_and_others` | 国家・他者への見方。担当国家の具体的資源や利益は不明のまま |
| `tensions_and_vulnerabilities` | 矛盾・弱点。矛盾を解消せず、無理に作ることも求めない |
| `conditional_principles` | 経験から形成された、状況認識に応じた判断の進め方。可変長 |

氏名・性別はPhase 1からの参照として固定し、Phase 2で再抽選しない。現在人物の形成に必要な解釈は生成できるが、過去の出来事を差し替えたり追加の過去事実を根拠として創作したりしない。人生と矛盾する明確な事実変更は確認して停止する。自然な葛藤・変心・自己矛盾は事実変更とは区別する。

各原則の提案欄は `perceived_condition`、`what_matters`、`judgment_tendency`、`deliberation_style`、`exceptions_and_tensions`、`life_refs`（根拠の人生区間）。原則の件数・状況は人物自身の設定に応じて生成し、共通の危機イベント一覧を渡さない。将来必ず選択する行動や、世界エンジンへ直接つなぐif文にしない。

## 5. 17軸評定の再提示

過去に正式採用・実行したschemaは16軸。旧17軸案は「意思決定速度も数値にする」という比較候補までで、17番目の正式キー・詳細定義は未採用だった。今回は16軸の意味を引き継ぎ、17番目を下記の案として提示する。v0の凍結済みschemaは変更しない。

**この工程の「測定」は、LLMが人物記述を読んで行う事後評定を意味する。心理検査で検証済みの尺度、本人の真の内面、行動確率、能力や善悪の点数ではない。** 評定値は生成済み人物を書き換える入力にしない。

| # | 軸・保存キー | 評定する傾向（低→高） |
|---:|---|---|
| 1 | 共感性 `empathy` | 他者の立場や苦痛を感じ取り意識に留める傾向。弱い→強い。救援を選ぶかは別 |
| 2 | 初期信頼 `initial_trust` | 情報が少ない相手の言葉・意図を信用する初期期待。低い→高い |
| 3 | 警戒心 `vigilance` | 隠れた危険・裏付け不足を確認する傾向。弱い→強い |
| 4 | リスク許容 `risk_tolerance` | 見積もれる損失可能性を受け入れる傾向。避ける→受け入れやすい |
| 5 | 不確実性耐性 `ambiguity_tolerance` | 確率・状況が分からない状態を抱えて判断する傾向。弱い→強い |
| 6 | 非情さ `instrumental_harm_tolerance` | 必要と考えた目的のため認識した他者の損害を受け入れ得る傾向。抵抗が強い→受け入れやすい |
| 7 | 妥協性 `compromise_readiness` | 自分の要求の一部を調整する傾向。弱い→強い |
| 8 | 報復傾向 `retaliation_tendency` | 被害・裏切りと認識した後に対抗的に応じる傾向。弱い→強い |
| 9 | 規範遵守 `norm_commitment` | 約束・規則そのものを判断理由として重んじる傾向。弱い→強い |
| 10 | 結果重視 `outcome_orientation` | 選択の帰結を比較して判断理由とする傾向。弱い→強い。全体利益最大化の命令ではない |
| 11 | 長期思考 `future_orientation` | 遠い将来の影響を現在の判断へ含める傾向。弱い→強い |
| 12 | 情報共有 `information_openness` | 知っている情報を伝える基本姿勢。秘匿寄り→共有寄り |
| 13 | 権力欲 `power_seeking` | 権限・影響力の獲得と維持自体への欲求。弱い→強い。主導能力とは別 |
| 14 | 責任感 `responsibility_ownership` | 自分の役割・決定の結果を引き受ける傾向。弱い→強い |
| 15 | 自国利益の重み `national_interest_weight` | 自国の利益・安全を判断へ含める強さ。弱い→強い。常時優先の命令ではない |
| 16 | 他国への配慮 `external_welfare_weight` | 他国の損失・生活を判断へ含める強さ。弱い→強い |
| 17 | 意思決定速度 `decision_speed`（今回の定義案） | 同程度の情報・判断機会で、決断を確定するまでの確認・熟慮を長く続ける→早く確定する傾向。能力・正確さ・API応答時間とは別 |

各軸は0〜100の整数、合計制約なし。0は傾向がほぼない、50は中程度、100は強いという共通アンカーを使う案。1点差の実証的精度を主張しない。相反する値を許し、他軸の逆数・正規化・相関制約・人数割当は使わない。APIの所要時間を17番目の値に代入しない。状況差は根拠と原則へ残す。

### 評定結果の保存形式案

機械可読案は [17軸評定schema](PERSONA_GENERATOR_V1_MEASUREMENT_SCHEMA.proposed.json)。各軸に次を保存する。

| 欄 | 内容 |
|---|---|
| `value` | 評定可能なら0〜100。根拠不足の場合は欠測nullとする提案 |
| `status` | `rated` または `insufficient_evidence` |
| `supporting_refs` | 固定済み人生史・現在人物・判断原則の参照先 |
| `rationale` | 人物のどの記述からその評定を行ったかという説明 |
| `counterevidence_refs` | 異なる読み方を支える記述がある場合の参照。なければ空配列 |

**根拠不足を50や0へ埋める方式は採用しない。** 0〜100は測れた値の範囲であり、nullを点数とは扱わない。欠測を許す上記の案と、その時点でPhaseを不成立として停止する案を比較できる。提案は欠測も観測として保持し、完成記録に欠測軸を明示する方式。schema確認時にこの扱いも確認する。

`rated`なら非nullの値と有効な根拠参照1件以上、`insufficient_evidence`ならnullと理由を要求する案。これは採点の正しさを機械的に証明するものではない。測定器には他人の人物像・既存の数値・v0/v1比較結果・「多様に採点せよ」という要求を渡さない。

## 6. 自己紹介・他者認識・Simulationの分離

Phase 4は「初めて他国のLeaderたちと会う本人として、何を伝えるか自分で決め、200〜300文字程度で自己紹介する」とする。内部数値の読み上げ、望ましい人物像の演出、誇張や隠蔽の強制はしない。

自己紹介は**本人が他者へ表明した自己像**。真の自己認識とは断定しない。内部人物構造、自己紹介、他者が表明した認識、Simulationでの実際の行動を別記録にする。自己紹介と内部設定が完全一致しなくても人物を修正しない。

Phase 1〜3は他国Agentへ直接配布しない。自己紹介を初回人物情報として使う方針を維持する。以後の認識は、到達した発言・観測可能な行動・世界内で取得した情報に基づく。生成器の全記録を共有メモリに入れない。

既存のSimulation入力方式Cの採用記録は取り消さない。ただし今回の生成器では測定値を人物形成・自己紹介へ戻さない。将来Cへ17軸の事後評定を接続すると、観測用の値が本人の行動入力にもなる。**その接続は今回実装せず、Simulation前に目的との整合性を確認する。** 無断でD方式へ切り替えない。

## 7. 本番人物の記録と確認

多様になったことを成功条件にしない。工程の独立性・順序・時間整合性・記録の追跡性を確認し、生成された人生・人物・年齢・性別の自由記述・17軸事後評定・自己紹介・判断原則をそのまま保持する。欠測を0や50へ補完せず、成功・失敗・中断・未実行を区別する。

**既存8名を新しい人物の生成入力や集計に混ぜず、v0の再評定・比較実験も行わない。** v0は別の保留索引で参照する。名前や経歴から性別を補完せず、v0の後付け属性も転用しない。

大規模な生成分布監査、軸間相関の一括探索、全人物間類似度の網羅的比較は今回の工程に含めない。人物が似ていても修正・再抽選の理由にしない。途中でprompt・schema・評定方式を変更する必要が生じたら停止し、異なる生成条件の人物を同じ集団へ黙って加えない。

## 8. 実行設定・検証・停止の提案

- modelはv0と同じ `gemini-3.6-flash`、Standard、temperature 1.0、candidateCount 1、thinking LOWを候補とする。seed/topP/topKは未指定の事実を記録。設定変更で偏りを解消したことにしない。
- 実行前に本番人物の生成枠と手順を固定し、1人ずつPhase 1→2→3→4→5を処理する案。各要求は新規contextで、許可した同一人物の記録だけを明示的に入力する。別枠の比較pilotは行わず、技術障害時の停止を維持する。
- 各Phaseの成功・固定を確認してから次へ進む。最初の通信・JSON・schema・時間整合性・保存障害で後続要求を停止。自動修正、再送、別model、追加人物への差替えは0回。
- 自己紹介の200〜300文字は目安。範囲外を注記して原文保持し、無断短縮や再生成をしない。年齢、性別、経歴、人格の偏りは失敗理由にしない。
- 17軸の値の矛盾は修正しない。参照先の不存在、`rated`なのにnull等は形式不備。根拠不足による正式な欠測は人物生成失敗と区別する案。
- 人物生成用Phase 1・2のschemaに人格軸の欄や説明を混入させない。共通の全Phase schemaを丸ごとモデルへ送らない。
- 各Phaseの実送信bodyの順序を保存する。hash用のキー整列と送信bodyを分離し、監査で見つかった項目順の入替えを引き継がない案。Phase境界そのものは別要求として維持する。
- 承認後、実装をオフライン検証してから初回要求へ進む。入力漏れ、他人格の混入、数値の逆流、原文変更、年齢の先行指定、失敗後の追加要求を検証対象とする。今回そのruntimeはまだ作らない。

Phase別の入出力上限、時間見込み、通常費用、最大予約額、USD停止上限は非公開の実行前確認メモで提示する。残高・入金・開発相談を研究文書や公開Evidenceに含めない。tokenの実数は生成前に未確定であり、見積を実測値とは扱わない。

## 9. Evidence保存案

各人物のPhase 1〜4について、manifest、実送信request、HTTP応答原bytes、時刻、応答ID、usage、schema/prompt版、source hash、成功・失敗・中断を保持する。原文は解析前に保存し、次Phaseへ渡したデータと元記録の対応をhashで結ぶ。取得不能は取得不能のまま残す。

```text
<life-first-v1-batch>/
  plan.json                        # 承認した条件、本番人物の生成枠、実行順
  leader-001/ ... leader-012/
    phase-01-life/                 # manifest / RAW / terminal / DERIVED
    phase-02-person/
    phase-03-assessment/
    phase-04-presentation/
    freeze.json                    # 各Phaseへの参照とhash、欠測、完了状態
  DERIVED/validation/              # 各Phaseの整合性・参照・欠測の確認
<preliminary-v0-reference>/        # 元8名を保留する別索引。RAW自体は移動しない
```

人生・人物・紹介のモデル応答は「架空人物生成のRAW」。17軸評定のAPI応答は「評定器応答のRAW」であり、その値を整理した表は「人物記述からのDERIVED」。評定値をSimulationで実測した行動データと混同しない。

生成方式version、Phase、人物ID、generation ID、model/version、generation config、seed指定有無、timestamp、schema版、wire hash、Evidence hash、親Phase hashを結ぶ。schemaやrequestの順序を含む実送信表現も保存する。APIキー・認証header・個人の開発相談・ローカル個人パスを送信／公開資料へ含めない。

各Phaseで保存し、Phase 5で全体を封じる。途中失敗を最後のFreeze待ちで未保存にしない。正式人物が完成した後の評定・紹介失敗も、既に固定した人生や人物を再生成する理由にしない。

## 10. 今回の確認と停止地点

Simulationは12国家で構成される単一世界へ12名を1対1配置し、同じ世界を3 TURN観測する1 runとし、旧8名は予備実験として保留する。確認用の具体案は、(1) 連続区間による人生と年齢の整合、(2) 意思決定速度を加えた17軸と根拠不足の欠測、(3) 原則はPhase 2に含め4生成／人、(4) 自己紹介へ測定値を戻さない、(5) 本番人物の生成に対応する費用・実行上限。

具体案と対応する非公開費用見積を確認してから、実装・オフライン検証・本番人物の生成へ進む。今回は設計更新のみで停止する。取り消した計画の実行枠・費用上限を流用しない。国家生成・Simulation・公開を人格生成と一括して自動実行しない。
