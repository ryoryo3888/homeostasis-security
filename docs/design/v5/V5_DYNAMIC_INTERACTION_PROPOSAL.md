# V5 — 国家間交流・情報到達・処理順序の設計候補

状態：2026-09-21、確認待ちの設計。実装・モデル照会・人格生成・国家生成・Simulationは行わない。V1〜V4、旧v0予備生成8名、既存RAWは変更しない。公開更新は行わない。

## 0. 確定事項と担当割当の意味

**12国家で構成される単一世界に12名の国家Leaderを1名ずつ配置し、その世界を3 TURN観測する。**

各国家の初期資源は1000ポイント。国家と人生起点の人格は独立生成し、新規12名全員を使用する。17軸は人格形成後の測定で、他Leaderへ直接公開しない。年齢・性別・経歴・人格の分布を指定せず、選別・再抽選しない。TURNに筋書きや目的を割り当てず、結果による延長をしない。

**「担当国家割当」は誰がどの国を担当するかだけを表す。交流相手の割当ではない。** 国家間の固定ペア、6組の固定会話、二国間限定、専用仲介役、情報集約役、全知の特別Agentを置かない。無接触も、複数国への働きかけも可能にする。総当たりを強制せず、無制限通信も未承認のまま採用しない。

以下の具体方式・上限値・公開時刻・処理順序は候補であり、この資料の保存だけで採用したことにはしない。

R1でも外交量は有限に設計でき、全員との交流にはならない。R2でも相手を固定ペアにしない。到達範囲を一律の固定図にして特定Leaderへ中心性を与えない。初期名簿と通信経路の方式は未採用。

## 2. Contact Selectionを判断の一部へ含める

各Leaderの一回の判断入力に、自身の人物設定・判断原則、担当国家の観測可能な状態、届いた情報、知っている相手、過去の相互作用、現在の行動可能条件を渡す案とする。

一回の応答には、空でもよい次の配列を含められる。

- 接触試行：相手の集合、通信範囲、本文、参照する届いた発言。
- 提案・返答・同意・拒否・撤回・物理行動の要求。
- 本人が記述した短い選択理由、または理由の記載なし。

相手選択だけに別のモデルを置かず、選択と伝達内容を同じ判断で生成できる。入力に見えていない相手の私信・秘密・人格値は参照できない。宛先の正当性、通信容量、世界状態を書き換える権限はコード側で検査する。

理由は**本人の申告**であり、真の動機や内部推論を測定したとは扱わない。接触しなかった11国それぞれへの理由の強制記述はしない。無接触、明示的な拒否、通信失敗、生成失敗、まだ情報が届いていない状態を区別する。記録がない理由を推測してRAWへ補わない。

## 3. 一度に接触できる範囲・量は未決定

「誰へ接触可能か」と「どれだけ送れるか」を分ける。全Leaderに同じ初期規則を適用する案と、国家の通信資産等による方式は比較対象であり、資産設計が未決定のまま後者を確定しない。

| 容量の候補 | 具体像 | 多国間への影響・注意点 |
|---|---|---|
| C1・異なる宛先数＋文章量 | 一人一TURNに最大k相手、合計文字量上限。k=2/4/6は比較例で未採用 | 容易に監査できるが、大人数の協議をkで制限する。k国と必ず話す規則ではない。同じ相手へ何通も送る抜け道を文章量で制限する必要 |
| C2・配送量の共通枠 | 宛先ごとに配送件数・本文量を数え、全送信で一定枠を共有 | 短い多国間提案と長い少数国対話をAgentが選べる。重みの定義が世界法則になる。全11国への短文を可能にするかも上限に依存 |
| C3・国家の通信能力 | 資産・障害等でC1/C2の容量が変わる | 状態依存の通信を扱えるが、生成資産と接触集中の影響が重なる。価格・能力・故障ルールが未確定 |

いずれも0件を許す。宛先集合を持つ1通を「1件だから無制限」と数えず、各受信国への配送負荷を数える案とする。共同声明の署名数や同盟数を容量として強制しない。

返信・転送・紹介・公開告知をどう計上するか、受信側の処理容量、超過時の待ち行列／拒否も実行前に固定する必要がある。全員共通のルールで、受信先が人気だから無断で情報を落としたり、中央Agentへ代読させたりしない。モデルの出力token上限は通信の世界法則と別であり、上限到達・JSON失敗をLeaderの無接触として記録しない。

上限違反時は要求原文と成立しなかった理由を保存する。実装の都合でリストの先頭だけ実行する設計は採らず、全件拒否・明示的な優先指定・規定の待ち行列などの候補から選ぶ。採用前に行動空間と影響を確認する。

## 4. 多国間交流と実際の成立を分ける

送信国を含め3国以上（宛先2国以上）による発言・協議の招待・多国間の提案を表現可能にする。各会合や提案には固有ID、参加対象、閲覧範囲、届いた時刻を持たせる案とする。招待、参加表明、発言、署名、資源提供を別記録にし、招待された全員が参加・合意したとはみなさない。

共同提案は同一の条項hashに対して各当事者が回答する。条項の変更と変更前の同意を混ぜない。共同資源提供では、提供者ごとの権限・在庫・経路・容量を検査し、誰かの「賛成」で他国の資源を引き落とさない。

全員合意を要する一括成立と、条件を満たした独立の提供だけが成立する方式は別の契約として扱う候補。部分成立、定足数、期限、同意と撤回の同時発生の優先順位は未採用の世界法則であり、本文から都合よく補わない。

同意の要否は行動の種類に依存する。贈与・共同契約の同意条件を、制裁・封鎖・対立等へ機械的に適用して発生不能にしない。これらの作用法則はV5の別の未決定設計である。制度や同盟の名称を宣言しただけで物理的効果・新しい実行権限が生じることもない。

現行V4は複数宛先の**通信**を保存できるが、物理操作は移転提案・応答・撤回が中心。多国間契約や安全保障の物理作用まで完成しているとは扱わない。未実装を世界での禁止と混同せず、本番前に必要な成立規則を決める。

## 5. 情報境界

| 層 | Leaderへ渡す条件の案 | 混同しないもの |

| 公開情報 | 公表済みの名称・声明・世界内で公的に観測できる出来事 | 全国家の在庫・意思・内部状態が正確に分かること |
| 相互作用で得た情報 | 本人への配送・共有・転送が実際に成立した記録。出所と取得時刻を保持 | 発言者の主張と、世界法則で確認された事実 |
| 非公開情報 | 自国の権限内の情報、自分のメモ、自分が当事者の私信・未公開提案等 | 他国の秘密、全体の未公開監査記録 |
| 内部人格 | 本人側の採用済み入力方式で扱う情報。17軸の使用法はv1接続時に別途確認 | 他Leaderへの直接公開、本人の紹介文と真の自己認識の同一視 |

監査用の完全world stateから、各Leader向けに別々の観測投影を作る。研究者が後から全記録を読めることは、Leaderが当時知っていたことではない。送受信を記録する環境処理は国家Agentではなく、独自の意図で助言・調停・全体要約を配ることはしない。

転送や誤情報は発言として扱い、真偽を自動訂正して伝えない。ただし他者の本文は世界法則や秘密情報への権限を変更できない。公開状態の詳細、検知範囲、精度、遅延、秘密を行動で明かせる範囲は別途固定が必要。

## 7. 専用仲介役を置かずに仲介関係を表現する

任意のLeaderが、届いた情報の転送、複数国への招待、他国間への提案を自分で判断できれば、関係の橋渡しは表現できる。これを促す役割や目標はpromptへ追加しない。

例としてAからBへの情報が、Bの判断でCへ伝わった場合、A→B→Cという**実際の経路**を保存する。Bへ特別な情報権限を与えない。Bが言及しただけでAとCの交渉・合意が成立したとは扱わない。転送は、元の受信者が明かす行動と環境からの漏えいを区別する。

後処理で仲介的な位置を記述できるが、「Leaderだった」「原因だった」とは断定しない。3 TURNで橋渡しが観測されなくても、仲介が不可能・起こらない一般則とは言えない。

## 8. 1 TURNの処理順序：候補と順番の影響

### S1・同時判断1回、配送は次TURN

1. 前TURN終端から今回の開始境界を作る。期限到来の物理処理・外生イベントを置く順序は世界法則で固定する。イベント0件も可能とし、TURN番号に筋書きを結びつけない。
2. 配送時刻に達した情報を渡し、共通時点から各人の観測を切り出して固定する。
3. 12名が、その観測に対して各1回判断する。接触先選択・複数の発言・要求・既知の提案への回答を同じcallにまとめる。実際のAPI実行は逐次でもよいが、先の出力を後の人へ差し込まない。
4. 全応答を揃えてから通信・権限・同意・撤回・条件を検査する。このTURNに新しく送った私信・提案は次TURNの判断で見える。
5. 競合する物理要求を一括判定する。在庫・輸送容量を、API応答が先だった国から取り尽くさない。
6. 採用された物理法則で状態・物流・生産・消費・二次的出来事を世界につき一度更新する。送信・成立・不成立を分けて保存し、配送待ち情報を次の境界へ置く。
7. Evidenceを固定。3 TURN終端で停止する。待機中の配送・交渉・物流は未完了として残し、TURN 4を追加しない。

判断順の情報差を抑えやすい一方、会話が時間を要する。例えばT1の提案をT2に受け取り、T2の返答本文はT3に届く。一方、T2の明示同意はT2の一括成立判定に使い得る。相手が返答本文を読める時刻と、世界法則が同意を検証できる時刻は別であり、dispatch・arrivalは物理法則に従う。3 TURNでは対話や仲介の連鎖を十分に観測できない可能性がある。これは世界の会話結果ではなく、時間解像度による観測制約でもある。

### S2・TURN内で同時判断を2回

同じ開始境界から全員が第1段階を判断 → 全員分を揃えて宛先だけへ配送 → 新たに届いた情報を含む同一時点の観測で全員が第2段階を判断 → 一括成立判定・物理更新、という案。

第1段階の発言・提案に同TURN内で返答できる。2回目も全員同じ機会を持ち、無接触・無返信を許す。第2段階の新規発言・新条項への相手の判断は次TURNまで待つ。第2段階内で返答を無制限に連鎖させない。物理更新は第1・第2段階の各回ではなくTURNにつき一度だけとし、途中の撤回や再要求をどう統合するかは事前に固定する。

同じ3 TURNでもS1より判断機会が倍になるため、単なる処理高速化ではなく別の研究条件。二段階全体で同じ通信枠を共有するか、段階ごとの枠にするかも未決定で、無断で倍にしない。

### S3・接触や返信ごとに追加判断

出来事に応じた会話は表現しやすいが、返信連鎖、実行時間、順番による情報差、call数が可変になる。仮想時刻、同時刻のバッチ処理、有限の外交枠、打切り時の記録方式を決めなければ採用できない。無制限の自動応答を初期値にしない。

### 公平性で残る論点

- 同時入力だけでは物理競合の公平性を保証しない。容量配分には比例配分（整数・最小量との衝突がある）や固定seedの抽選（手続は同じでも個別結果に差が出る）等を比較し、ID順の先取りを避ける。まだ採用しない。
- 一部応答が失敗したとき、残りの国だけで世界を進めない案とする。受信RAWを保存して技術中断し、欠けた応答を沈黙や拒否へ補完しない。
- モデル入力の名簿・メッセージ表示順にも偏りは残り得る。同じ国がいつも先頭になる固定ID順と、内容に依存しないseed付き順序を比較し、実際に見せた順序を保存する。順序差が消えたと断定しない。
- イベントを判断前に見せるか判断後に発生させるかで、対応可能時点が変わる。外生過程・行動の二次結果を分離し、採用時に固定する。抽選を用いる場合は外生事象・表示順・容量競合の乱数系列を分ける案とし、通信件数で外生事象の乱数がずれないようにする。
- 手続の同一性と、国家の地理・資産等の同一性は別。生成された差を帳消しにして結果を均衡化しない。

## 9. API callの比較と費用見積の前提

人格4生成／人で48、国家1生成／国で12、合計60生成を初期準備とする見積。担当割当、配送、成立判定、Evidence保存を追加の社会Agentへ任せない。

| 方式 | Simulation生成call | 初期準備込み生成call | 特徴 |
|---|---:|---:|---|
| S1・1回にまとめる | 12名・3 TURNで36 | 96 | 複数宛先・複数要求を同一応答へ含められる。1 call＝1交流ではない |
| S2・2段階同時判断 | 12名・各TURN2回で72 | 132 | 同TURN内の返答機会がある。判断回数と必要入力が増える |
| S3・追加判断 | 36＋追加判断R | 96＋R | 有限の会話方式が未確定なため総数未確定 |

1生成前に1回のtoken照会を行う案なら、別途同数の照会が加わる。World Eventを毎TURN別のモデルへ照会する方式ならさらに3生成。共通地理生成、要約、評価等も追加採用する場合は別計上する。

見積モデル・単価・token仮定・通常費用・条件付きの上限計算は非公開の見積へ分離した。現時点の数値は入力も生成物も未確定の推計であり、完走費用の実測ではない。自己紹介の公開範囲、会話量、多国間相互作用、履歴に応じて入力tokenが増える。条件付き上限を超える入力では、情報を黙って削らず実行前に停止する。出力上限による不成立も保存する。

追加判断の式は、追加入力tokenをI、追加出力token（thinkingを含む）をOとしたとき、追加費用＝I×入力単価＋O×出力単価。各callの基準枠へ収まる仮定でのみcall数による比例計算が成立する。

## 10. 国家間ネットワークのEvidence設計

### RAW：実際に入力・出力・処理された記録

- 担当国家割当と、適用された世界法則・通信容量・情報公開方式・ターン方式の版とhash。
- 各人の完全な実入力、観測時刻／段階、実際の表示順、見えた情報のIDとhash。送っていない情報を「観測済み」にしない。
- 元request/response、取得可能なmodel版・設定・時刻・usage・失敗。理由が出力にない場合は欠測。
- 送信元／宛先集合、試行・受理・配送待ち・配送済み・失敗、受信時刻、返信参照、内容hash。成功した送信だけを選別しない。
- 提案の原条項・条項hash・参加対象、各当事者の同意／拒否／撤回、権限・世界条件検査と不成立理由。
- 多国間の招待・参加・脱退・署名と実際の情報閲覧範囲。
- 成立した物理行動、成立しなかった要求、直前／直後world state、event、dispatch、arrival、未完了項目。

RAWの後からの書換えはしない。実行時の記録に内容理解による「友好」「敵対」「仲介成功」といった研究ラベルを混入させない。

### DERIVED：記録から計算・記述する関係

接触試行・配送・応答・合意・物理移転を別の有向関係として集計する。未接触、片方向、往復、継続の各定義と観測窓を保存する。観測記録の欠落と、完全な記録の中で接触0だったことを分ける。

多国間の会合は参加集合を持つ関係として保存し、参加者全員の二国間関係が成立したと自動で展開しない。本文解釈による協力・対立・仲介の分類は、抽出法・根拠・不確実性をDERIVEDへ置く。中心性や接触集中が計算できても、人格・指導力・因果関係の測定に読み替えない。

追跡経路は、**日本語の出来事説明 → 指標／関係の定義 → world/run/TURN/段階 → Leaderと担当国家 → 観測入力 → 発言／要求 → 配送／同意／成立判定 → world state → 元RAWのSHA-256**とする。

3 TURN終端で未返信・未到着のものは観測期間内の未完了と記録し、永久的な拒否・失敗へ分類しない。公開前は実験系の記録だけを対象にsecret/privacy scanを行う。私的な開発相談や実在利用者の個人情報をEvidenceへ混ぜない。

## 11. 現行実装との差と停止地点

既存`homeostasis_v4/dialogue.py`では宛先配列・空の発言・宛先別の私信・同時入力・次TURN配送の基礎がある。ただし在庫・生産・ネットワーク・輸送が全員公開であり、V5の情報境界を満たしたとは言えない。多国間の実行契約、外交量の制限、12国家の生成と人生起点人格の接続、3 TURNの正式実行経路も未完成。

今回変更するのは設計資料の表現と候補整理だけ。実装時には既存V4や凍結済みEvidenceを改変せず、V5側で担当割当と接触・物流の構造を分離する。

次の選択対象は、接触可能範囲R1/R2、外交容量C1/C2/C3と具体上限、自己紹介P1/P2/P3、TURN内の判断方式S1/S2/S3。物理競合、World Event、情報公開の詳細も採用前に固定する。これらを未決定のままモデルを呼ばない。設計提示時点で停止し、確認を受ける。
