# ローカルLLM動作確認 — 2026-09-19

MacBook Air M1・8GBにOllama 0.34.2とQwen3 1.7B（Q4_K_M、約1.4GB）を導入。
localhost限定で実行。従量制API呼び出し0、新しい有料契約なし。

以前のGemini拡大比較のseed17 / TURN1 / ECONの入力をそのまま使用。
システム文、利用者入力、JSONスキーマの完全一致を確認した。
温度0.3、seed17、出力上限1536は同値。トークナイザー・推論基盤・サンプリングの実装は異なる。
ローカルはthinking=false、Geminiはminimalであり、内部推論量の同等性は保証しない。

入力31,307トークンを40,960の枠で切り捨てず処理。約368秒で応答。
モデルは自国の最大1提案という制限に従わず、他国の候補も含め多数の取引を列挙し、
1,536トークンの上限でJSONが途中終了した（done_reason=length）。
回答は補修・間引きせず、未完了として不採用。確定TURNは0。

この端末でローカル推論が動くことは確認できた。一方、この軽量モデルのこの試行は
Geminiと同条件の比較に使える国家判断を返せなかった。ローカルLLM一般の評価ではない。
入力を短くする・出力形式を変える場合は、Gemini側も同じ変更を適用した別実験にする必要がある。

原本は `.artifacts/local-llm/probe-request.json` / `probe-response.json` / `probe-result.json`。
モデルと原本はGit非公開。Ollamaのログイン時自動起動は設定していない。
